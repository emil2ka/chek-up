# Публикация

Ничего из этого не делается само: нужны аккаунты и ключи владельца проекта.

1. **База.** Supabase через интеграцию Vercel (Storage → Supabase): строки подключения попадут в проект сами. Миграции идут при выкладке основной версии (`web/vercel.json`). Своя Postgres: `cd web && DATABASE_URL=… pnpm db:migrate`. Миграция `0002_families` сама превращает старые анонимные аккаунты в семьи из одного человека.
2. **Переменные сервера** — по образцу `web/.env.local.example`. Обязательны `DATABASE_URL` и один ключ распознавания. Без `DATABASE_URL` сервер на хостинге откажется работать с данными, чтобы не потерять чеки.
3. **Вход.** Почта: домен в Resend, `RESEND_API_KEY` и `MAIL_FROM`. Google: OAuth-клиент типа Web, домен сайта в «Authorized JavaScript origins», его ID в `GOOGLE_CLIENT_ID`.
4. **Сайт.** Vercel, корень проекта `web`, регион Франкфурт. После запуска `/api/health` должен ответить `"db":"postgres"` и `"scan":"ai"`. Пока не задано `PUBLIC_INDEX=1`, поисковики сайт не видят.
5. **Бюджет распознавания.** Один чек стоит около 0,3 ₸. Потолок задают `SCAN_DAILY_CAP` и `SCAN_USER_CAP`; поставь лимит трат и у провайдера ключа.
6. **Приложение.** `flutter build ipa` / `flutter build appbundle` с `--dart-define=API_URL=https://адрес-сайта`. Нужны аккаунты Apple Developer и Google Play, подпись и значок. Минимальная версия iOS — 15.
7. **Перед открытием людям:** вычитать казахский, проверить страницу `/privacy`, прогнать десять настоящих чеков разных сетей, проверить письмо с кодом и вход через Google на настоящем домене.
